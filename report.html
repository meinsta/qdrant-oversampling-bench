Oversampling buys recall.
Here is what it costs.

Qdrant's docs say oversampling trades speed for quality and suggest 3×. No published source puts both numbers on one chart for one dataset. This is that chart: one collection, one query set, recall and p95 latency recorded together at every setting.

The finding

The tradeoff is real, but its slope is set by how many results you ask for. At k=10 the entire sweep from 1× to 16× costs 0.22 ms of p95 and buys 7.3 points of recall — the knob is close to free, and there is no reason to run it low. At k=100 the same sweep costs 2.0 ms, and every step past 4× is paying real latency for hundredths of a point.

The more useful result is where the curves cross plain HNSW. At k=100, binary quantization at 3× oversampling with rescore beats un-quantized HNSW on both axes — 0.9946 recall at 1.49 ms against 0.9877 at 2.25 ms — while using a 32× smaller index for search. Qdrant's recommended default lands exactly on the useful part of the curve.

The one setting to never ship

Binary quantization with rescore off

0.6725 recall@10 and 0.6873 recall@100 — and oversampling cannot rescue it, because there is nothing to re-rank with. It is the fastest row in the table and the only one that is wrong. The docs say rescore is required; measured, "required" means a third of your results.

How it was measured

  • Dataset. KShivendu/dbpedia-entities-openai-1M — DBpedia entity text embedded with OpenAI text-embedding-ada-002, 1536 dimensions. First 100,000 rows indexed; the next 1,000 held out as queries. No query appears in the index.
  • Ground truth. Exact KNN over the same collection (exact=true, quantization ignored), following Qdrant's documented ANN-recall method. Recall is the overlap of the approximate and exact id sets, divided by k, averaged over 1,000 queries. This measures index and quantization loss only — not whether the embedding model retrieves the right thing.
  • Index. Default HNSW (m=16, ef_construct=100, default query ef), binary quantization with always_ram, original vectors in RAM. Collection green and fully indexed before any timing. Rescoring from disk is a different and much slower story; it is not what these numbers show.
  • Timing. 1,000 sequential single queries per configuration over local gRPC, 50-query warmup, client-side wall clock. That includes roughly a third of a millisecond of transport, so read these as relative distances between configurations rather than as an absolute service latency. No concurrency — throughput under load is a separate measurement.
  • Scope. One dataset, one embedding model, one node, 100k vectors. Binary quantization is sensitive to dimensionality and to how the model distributes its components; 1536-dimension OpenAI vectors are its best case. Re-run before quoting these numbers for a different model.
