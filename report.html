Two ways to buy recall.
One of them is three times cheaper.

Binary quantization with oversampling, or an unquantized index with a bigger ef — both walk more candidates to find more of the true neighbours. Only one walks them as single bits. This is both frontiers measured on one collection, with recall and p95 latency recorded together.

The finding

At a matched ef of 300, binary quantization with rescoring beats the unquantized index on both axes at every limit tested. It needs more oversampling than the documented 3x to get there — and the multiplier it needs falls as the limit grows, because a larger limit already gives the rescore pass more candidates to work with.

How it was measured

  • Grid. Follows the parameter sweep in Qdrant's OpenAI binary-quantization article — oversampling x rescore x limit, limits 10/20/50/100 — and adds latency percentiles plus an ef sweep on both the quantized and unquantized side.
  • Dataset. KShivendu/dbpedia-entities-openai-1M, DBpedia entity text embedded with OpenAI text-embedding-ada-002, 1536 dimensions. First 100,000 rows indexed, the next 1,000 held out as queries.
  • Ground truth. Exact KNN over the same collection (exact=true, quantization ignored), per Qdrant's documented ANN-recall method. Recall is the overlap of the approximate and exact id sets divided by the limit, averaged over 1,000 queries. Every target is reachable by construction, so this isolates index and quantization loss and says nothing about whether the embedding model retrieves the right thing.
  • Why sweep ef at all. Oversampling raises the candidate count the index has to walk, so binary quantization at 16x does much more graph work than an unquantized search at the default. Sweeping ef on the unquantized side, and repeating the whole oversampling range at a fixed ef, is what makes the comparison apples-to-apples.
  • The default ef is 100. Leaving hnsw_ef unset gives recall identical to four decimals to an explicit ef=100 at every limit, which is this collection's ef_construct. Qdrant's docs do not state the default; this is what it measures as.
  • Index. m=16, ef_construct=100, binary quantization with always_ram, original vectors in RAM. Green and fully indexed before any query is timed. Rescoring from disk is a different and much slower story, not measured here.
  • Timing. 1,000 sequential single queries per configuration over local gRPC, 200-query warmup, client-side wall clock, nothing else running on the host. Roughly 0.3 ms of every figure is client and transport overhead.
  • Noise floor. p95 carries about 0.2 to 0.3 ms of run-to-run variation, so a few cells break monotonicity. The frontier gaps quoted here are 1 to 3 ms. Use p50_ms from the CSVs if you need finer resolution.
