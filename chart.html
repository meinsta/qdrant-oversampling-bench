Same accuracy, a third of the time.
That is what compression buys.

Binary quantization is less accurate than uncompressed search per candidate examined. It wins anyway, because 1-bit distances are cheap enough to examine far more candidates inside the same latency budget. Rescoring is what converts those extra candidates back into accuracy, and oversampling is what decides how many of them there are. Both curves below walk identical pools, so the only difference left is how each distance gets computed.

Recall is scored against exact KNN on the same collection, so 1.000 is reachable by construction and nothing here is limited by the embedding model. Oversampling pre-selects limit × oversampling candidates, so the matched uncompressed run is one walking the same size pool (hnsw_ef = limit × oversampling). A fixed hnsw_ef is not a control: below the pool size it is ignored, and above it it hands the quantized side a wider search than the uncompressed side gets. Latency percentiles are the median of three passes of 1,000 sequential queries on local gRPC, about 0.3 ms of which is transport. A latency win, not a memory win: rescoring keeps the float vectors resident. Method, raw results and the fuller report: meinsta/qdrant-oversampling-bench.
